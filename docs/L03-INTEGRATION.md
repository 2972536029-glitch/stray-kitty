## 独立试玩

新增 `greenhouse_boss`，catalog 的 lanes=6、columns=9、waves=8 表示包围尺寸和波数，不能把它理解成完整矩形。局内实际只存在 34 格，缺口 20 格，花房障碍 3 格，四格 Boss 位于 C6／C7／D6／D7，保护点 B1，入口 C8／E8／F7。详见 [棋盘设计](../design/tower-defense/levels/L03-abandoned-greenhouse/design.md)。

家园在第一章救援完成后可试第三章，不强制先通关第二章试玩，不推进正式第三章剧情。`BattleHost` 以真实 attempt ID 路由 `GreenhouseBattleViewport`；独立 context 校验 stage 和配置，读取服务保存的难度快照。

沿用 `START_BATTLE` 和 `COMPLETE_BATTLE`，结果报告包含 leaks 与 bossDefeated。服务验证完整报告、阶段、场次与幂等，胜利须 bossDefeated=true 且 leaks<3。客户端负责局内模拟，服务不做权威重演。

## 参数、结算与恢复

活动场次 shadowPressure 的 −1／0／1 对应 low／medium／high，缺省普通，非法值拒绝。只应用一次 0.8／1／1.2 敌人体力倍率，不重算随机事件评分。

L02／L03 共用独立试玩边界：胜利只记录本关完成，不发物品、邮票、家具、鼓励次数或长期伙伴，不消费主线待用修正；继续返回家园。失败后进入本关准备，新 attempt 复制失败场次难度，离开准备页时清理临时重试身份。

不新增动物事件或未经团队确认的战中协议。正式主线位置、战中参数的变更时点与后续剧情由团队标准确定后再对接。

标题暂停保留原局内实例；整页刷新从同一服务场次的 ready 重新构建，不是逐帧恢复。无本波重开、休整、物品或退场复活。

## 页面和验证边界

当前美术分支采用旧温室的苔绿砖面、花盆、碎陶与花架，以破窗微光表现环境，不额外指定昼夜；详见[场景美术](../design/tower-defense/scene-art.md)。保留猫旁技能，没有伙伴名单侧栏；军师保持本地规则。Canvas、交互格、部署、技能和路径均按实际存在地格裁切，缺口必须透明且没有交互按钮。三个白叉仍对应原花房障碍，外围氛围底色不扩展可用棋盘。
