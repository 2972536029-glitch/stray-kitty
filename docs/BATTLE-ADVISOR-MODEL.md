# 阿策：服务端模型问答

2026-10-28，独立开发分支 `feat/battle-advisor-model`。阿策通过服务端接入 DeepSeek `deepseek-flash`，六章战斗、技能、数值、胜负与剧情入口保持现有规则。

## 玩家行为

在原阿策聊天入口提问时，通过同源 Go 服务请求模型。模型可以结合眼前战况解释站位、血量、能量、技能和应对方式，只给建议，不获得移动、施法、改存档或结算权限。自动教学与主动战况提示继续由本地规则生成，不逐帧请求模型。

聊天沿用暂停规则。正在回答时阻止重复提交；关闭聊天、离开页面、切换场次或外部暂停会取消等待，过时回答不会塞进新场次。不自动重发被取消的提问。模型不可用时显示本地规则回答，不能把回退冒充模型成功。

每次只发送当前问题、最近三轮手动对话和当前章的可见战况摘要。摘要按字段白名单构建，包括现有地格、在场猫、公开技能规则和可见威胁；不直接发送完整引擎状态、会话令牌、存档、随机种子或未来波表。第四章隐藏敌人的位置和体力不进入模型上下文。角色规则按本章配置生成，避免第三章清棘与第四／五章夜视混用。

## 服务与配置

`POST /api/v1/advisor` 使用现有匿名会话 Bearer 认证。正文为 `attemptId`、`stageId`、`question`、`context`（JSON 对象的字符串）和可选 `history`；服务端校验活动场次，模型返回后再次确认场次没有结束或更换。聊天不占用游戏命令幂等通道，也不修改游戏 revision。

配置只从 Go 服务进程环境读取：

| 变量 | 值／用途 |
| --- | --- |
| `ADVISOR_BASE_URL` | 默认 `https://api.deepseek.com`；OpenAI 兼容服务根地址 |
| `ADVISOR_MODEL` | 默认 `deepseek-flash` |
| `ADVISOR_API_KEY` | 本地私有配置或部署 secret 注入；缺省时本地回退 |
| `ADVISOR_MAX_CONCURRENT` | 可选，全局在途上限，默认 4 |
| `ADVISOR_DAILY_REQUEST_LIMIT` | 可选，单进程每天尝试上限，默认 200 |

`.env.example` 仅为示例，不会自动读取。开发者需在启动 Go 前导出环境变量；不得使用 `VITE_` 密钥变量，不得把密钥放进客户端、仓库文档或构建产物。用户本机配置与试玩启动器保存在正式仓库之外，交付给队友时由各自环境提供凭据。

Docker Compose 的 `deploy/compose.yaml` 已透传上述五项变量。部署者可从私有部署环境注入，或通过 `docker compose --env-file <仓库外配置路径> -f deploy/compose.yaml up -d --build` 启动；不要把含真实密钥的配置文件提交到仓库或附在 MR 中。未提供密钥时仍可启动游戏，阿策使用本地规则。合并代码不会自动把本机密钥配置到团队服务器。

采用 [DeepSeek 官方 Chat Completions 协议](https://api-docs.deepseek.com/api/create-chat-completion/)，仅传文字，关闭 Flash 的 thinking，温度 0.2，要求 JSON `title`／`text`。通常用 80–220 字直接回答，最多三条建议；在场主力名单、数量与突破判定提供独立明确摘要。响应长度、结构和结束原因均校验，前端按纯文本显示。提供商错误正文和鉴权头不向玩家回显，也不写入日志；请求禁止携凭据跟随重定向。

## 边界与回退

- 每问最多请求模型一次，单次上限 12 秒，没有自动重试；HTTP 正文、上下文和历史条数均有限制。
- 每会话最多一个在途请求、每分钟最多 6 次；全局最多 4 个在途请求、每 UTC 日最多 200 次模型尝试。配额为单进程内存计数，重启会重置，不是跨实例计费上限；失败请求也可能占用尝试次数。
- 未配置、超时、限流、提供商故障或输出无效时，响应 `source: local`，客户端使用现有本地规则。输入无效、会话无效或场次过期由 API 明确拒绝，不继续调用模型。
- 模型以客户端白名单摘要为观察依据；当前战斗本身也是客户端模拟，这不是服务端权威战况验证或防作弊系统。
- 模型没有工具执行能力；自然语言回答仍可能有误，不能作为游戏规则或结果判定来源。

## 验证范围

离线测试使用模拟提供商检查认证、输入、限流、超时、错误回退、场次变化、只读状态与密钥边界；前端检查可见上下文、不同章节技能、取消与过时回答。真实供应商联调与浏览器验收记录留在仓库外，不能用模拟响应代替真实模型成功的证据。

本功能基于已有战斗和事件协助者代码。六章地图美术另有公共底座与分章分支；本地组合试玩可以共同展示，正式整合时仍需保留双方入口、布局和问答行为。
