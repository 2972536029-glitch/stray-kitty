# 阿策战斗与家园问答：AI 能力与接入方式

本功能最初基于 2026-10-31 的 main `c77df84b95bfe84d00511954e58c5631f3d98480`；2026-11-02 合并审查前已在本 AI 分支同步 main `9ce52b5eae35dcbf60ad87ccd7f76033d2dea2ba`。第 7 节保留各次验收对应的版本，不把旧版本结果当作本轮新增能力的验收结果。

AI 能力包括只读问答接口、当前可见信息整理、分场景回答、本地回退和可选的会话管理工具。2026-11-04 家园已通过 `HomeAdvisor` 接上顶栏「问阿策」和聊天面板，沿用 `AdvisorProvider` 与旅程接口；六章战斗继续使用原有问答。地图、剧情、事件、准备和结算页不新增入口。家园的出现时机、文案和公开剧情口径见第 5.1 节。

**2026-11-02 最终范围：本轮只在战斗页面和家园页面提供主动问答入口。**

| 入口 | 回答范围 | 事实边界 |
| --- | --- | --- |
| 战斗页面 | 当前战况、技能、阻挡、站位、胜负条件、当前支援和已公开的战斗规则 | 使用本场真实快照；家园、事件、资源经营或剧情等非战斗问题简短引导回家园询问 |
| 家园页面 | 战斗机制、家园修缮与家具、已结识伙伴、公开事件规则、当前资源和可核实的已知剧情 | 依据当前存档与筛选后的公开资料；没有实时战斗快照，不报当前血量、能量、站位或敌情，也不把旧聊天当成实时状态 |

这项决定替代此前“各阶段分别新增入口”及“事件弹窗主动问阿策”的接入提议。地图、剧情对话、事件弹窗、准备和结算页本轮均不新增入口；已有 `journey` 多阶段协议与 `explore_hint` 工具保留兼容，不构成这些页面的接线任务。家园问答范围覆盖游戏模块，不等于公开未来剧情、隐藏结果、未解锁伙伴或完整事件池，也不等于模型记住完整历史。

2026-11-01 以地图工作项 [Jenny 的最终范围确认（note 9290）](https://school-gitlab.xsolla.dev/haozhe_wang/stray-kitty/-/work_items/3#note_9290) 为准，替代此前 [四章自动润色建议](https://school-gitlab.xsolla.dev/haozhe_wang/stray-kitty/-/work_items/3#note_9205)：**本轮地图保留原有本地情境文字，不接自动 AI 改写，不新增地图聊天、指路或追踪入口。**目标资格、显隐、操作键和前置提示继续由地图现有规则处理。已经准备的 `useExploreAdvisorHint` 和相关 API 保留为可选工具，本轮未启用，也不要求地图负责人接线。

阿策只解释和建议，不替玩家决定探索路线、触发事件或推进地图。轩扬与剧情/AI 在现有 [UI 工作项 #5](https://school-gitlab.xsolla.dev/haozhe_wang/stray-kitty/-/work_items/5) 对齐战斗与家园两个入口；浩哲确认家园表现、口吻及公开剧情口径。地图不另加控件或重复任务。本文保留的可选工具说明及历史验收记录不扩大本轮入口范围。

## 1. 先选接入层级

| 方式 | 适合情况 | 提供的能力 |
| --- | --- | --- |
| 直接请求 `POST /api/v1/advisor` | 已有自己的聊天和状态管理 | 服务端认证、当前进度校验、模型调用与限流 |
| 使用纯函数和 `requestModelAdvisor` | 想复用上下文整理，自己管理界面/对话 | 当前可见信息、场景标识、本地回答、请求取消 |
| 使用可选的 `AdvisorProvider` / hooks | 想共用有限对话记录，界面仍自行制作 | 上述能力，加跨页最近三轮对话、旧回答取消、账号/QA隔离 |
| 保留的 `useExploreAdvisorHint` 工具 | 可选能力，本轮地图不接入、不启用 | 当前提示单句改写、去抖、低频缓存、过期取消、原文字回退；供未来另行确认后使用 |

以上能力不会自动移动角色、推进剧情、选择事件、修改存档、领取奖励或付款。

## 2. 家园使用旅程请求协议

家园使用现有 `scope: 'journey'`，战斗继续使用原战斗协议。两者均使用现有匿名/登录会话的 Bearer token，经同源 Go 服务请求；模型密钥继续只由服务端私有配置提供。`journey` 旧协议仍能处理其他阶段，但本轮接入方只在真实 `state.phase === 'home'` 时提供旅程问答入口，不伪造家园状态或额外在事件卡挂载入口。

```ts
import {buildJourneyAdvisorContext, journeySceneKey, getJourneyLocalAnswer}
  from '../modules/advisor/journey-context';
import {requestModelAdvisor}
  from '../modules/battle/model-advisor-client';

// 本轮用于家园入口；在玩家真正点击“发送”时读取最新 state/catalog。
// 保留真实phase，不能把其他阶段伪装成home来发送。
const abort = new AbortController();
const answer = await requestModelAdvisor({
  scope: 'journey',
  sceneKey: journeySceneKey(state),
  expectedRevision: state.revision,
  question,
  context: buildJourneyAdvisorContext(state, catalog, scene),
  history: [], // 可传最近三轮，共最多6条 user/assistant 消息
}, abort.signal);

const displayed = answer.source === 'model'
  ? answer
  : {...getJourneyLocalAnswer(state, catalog, question, scene), source: 'local'};
// displayed.title/text 按纯文本显示；保留 source 标签，说明是否为本地建议。
// 关闭页面、切换场景或账户时调用 abort.abort()，不自动重发。
```

| 字段 | 约定 |
| --- | --- |
| `scope` | 旅程请求为 `journey`；缺省或 `battle` 保持旧战斗协议 |
| `sceneKey` | `JSON.stringify([state.phase, state.chapterId, state.mapId, state.storyNodeId, state.pendingEventId, state.activeBattle?.id ?? ''])`，请直接用导出函数 |
| `expectedRevision` | 提问时最新的非负整数进度版本 |
| `question` | 1–500字；只在玩家主动提问时请求 |
| `context` | JSON对象的字符串，最多24000字；使用白名单生成器，不能直接序列化整个存档或内容目录 |
| `history` | 可省略，最多6条，仅 `user` / `assistant`，每条不超过1200字 |

家园 `journey` 请求不传 `attemptId/stageId`，也不提供战斗快照。旧战斗请求仍传这两个字段，继续使用 `buildModelAdvisorContext(stageId, snapshot)` 取得真实棋盘信息；战斗入口不借由旅程请求回答家园或剧情问题。

返回值仍为 `{source: 'model' | 'local', title, text, reason?}`。`source: local` 表示应使用当前场景的本地回答，并显示回退提示；不能标成模型成功。

HTTP 409 表示场次或当前进度已变化，客户端抛出 `AdvisorContextChanged`。此时应丢弃旧答案和旧场景的备用回答，提示玩家重新提问，不自动重试。400/401等错误也不得变成游戏命令或自动创建新存档。

## 3. AI 能看见什么

家园问答由服务端读取当前会话的可信进度与可公开的游戏资料，客户端只补充当前显示信息；战斗问答沿用真实棋盘快照。当前知识与观察边界如下：

家园阶段额外提供 `serverProgress.homeKnowledge`：通用战斗规则、已结识伙伴档案、已体验关卡的 `battleReference` 静态技能与基础属性、公开事件点数表、资源用途、已解锁家具/包裹服务，以及有记录的通关进度。`liveBattle.available` 固定为 `false`。战斗资料直接从六章现有配置生成，不含波表、敌人、初始站位或未体验关卡；通关/最近胜负记录能证明体验过关卡，不证明对应主线对白已经发生。资料文件只供 AI 读取，不参与玩法。改动战斗配置后运行 `node --import tsx scripts/advisor-battle-reference.ts` 更新资料，测试中的 `--check` 会检查其是否与配置一致。

- 当前阶段、章节、地图，已结识伙伴、已有资源、已完成关卡。
- 已知剧情依据存档中能核实的进度、已完成关卡与实际记录的最近事件回答；不按 flag 名称编造剧情，不宣称记得没有记录的旧台词或旧选择。旧技术协议若用于剧情阶段，只提供当前正在显示的一句，不提供未来节点链或整章剧本。
- 家园可以解释公开事件规则及存档里真实记录的最近一次结算，不扫描整池事件或未来选项。旧技术协议若用于事件阶段，只提供当前题面、可见选项和页面公开的骰点档位；最近已结算事件单列。隐藏结果不发送。点点陷阱洞察已经在页面展示的资源/压力摘要可使用。当前普通选项不要求或扣除库存物品，“放下鱼干”等叙事不等于库存费用；伙伴鼓励单独消耗鼓励次数，须在掷骰前使用。
- 家园依据当前修缮项目的部件、真实成本、前置和已完成状态回答。AI 摘要会合计目标及尚未完成的前置成本，共用前置只计算一次，再用当前余额计算总缺口；这只是建议用的计算，不扣款、不改变修缮规则。前置缺失或存在循环时不提供不完整的合计。
- 家园可解释已公开的通用战斗机制和已结识伙伴的能力；没有本场快照时，不提供实时血量、能量、站位、在场人数或敌情。历史聊天中的数值也不是当前事实。战斗继续使用六章现有快照，旅程伙伴名单不能替代在场战斗名单；喵喵是保护目标，阿策是顾问，均不计为战斗主力。准备阶段未提供真实阵容时，不推测上场名单。
- 资源名称固定区分：`food` 是鱼干，`material` 是修缮材料，`clue` 是线索，`stamp` 是猫爪邮票，`tuna` 是金枪鱼罐头。当前集市不能直接回家，离开方式以北侧出口规则为准。

不会发送支付流水、会话 token、完整存档、未发生的剧情或整份事件结果表。模型只提供解释和建议，不执行任何游戏操作。

服务端在请求开始时核对 `expectedRevision` 和 `sceneKey`；返回时核对语义场景和相关进度。单纯移动里程变化不会让正在生成的答案失效；事件选择、资源、修缮或场景变化会取消过期答案。

`GameState` 只有当前剧情节点、进度标记及有限结果记录，并不是完整的已读台词或选择日志。没有记录的信息直接说明无法确认；家园问答不会凭空补齐整段冒险历史。

## 4. 保留的可选观察协议（本轮不要求地图接线）

以下是已有 AI 工具支持的观察字段，供未来经统一确认的入口复用。本轮地图继续显示本地文字，不需要为这些字段新增数据采集、控件或模型请求。

```ts
interface JourneySceneObservation {
  nearby?: {id: string; label: string};
  position?: {x: number; y: number};
  floor?: string;
  inspectHint?: string; // 地图此刻批准的文字；换场景、完成或失效时清掉
}
```

缺少 `scene` 也能解释当前进度、事件和家园状态。若后续入口已获确认并提供 `nearby/floor`，工具可以说明已显示的附近对象和楼层。单纯坐标不等于可达路线，本版不会凭坐标编造转弯或寻路建议；精确指路不在本轮范围，也不要求地图新增路线摘要。

场景信息应取自当前地图模块的实际运行状态，不能沿用上一个地图的位置或交互目标。

工具层保留的主动问答行为是：有效 `inspectHint` 可作为当前地图目标，优先于通用进度提示，且只在探索阶段发送。此能力不会自行创建本轮地图问答入口。`nearby.id` 只在客户端用来识别观察变化，模型只收到已显示的 `nearby.label`，不会按内部 ID 推测陷阱、首领或后续剧情。

### 4.1 保留的探索短提示工具（可选，本轮未启用）

以下示例记录已有 SDK 的使用方式，不是本轮地图接入任务。未来如需调整地图范围，须先与地图负责人及剧情/AI、UI 工作项 #5 重新确认；启用时仍须沿用地图原有 `inspectHint`、`nearTarget`、楼层及 eligibility helper，**先由地图确定文字可见且允许润色，再调用工具**。[既有名称/ID 可见性附表](https://school-gitlab.xsolla.dev/haozhe_wang/stray-kitty/-/work_items/3#note_9206) 仅作边界参考，不能遍历附表寻找尚未显示的目标，也不能据此新增发现列表、追踪存档或寻路规则。本轮不挂载此 hook，原本地文字直接显示。

```tsx
import {useExploreAdvisorHint} from '../modules/advisor/useExploreAdvisorHint';

const hint = useExploreAdvisorHint({
  state,
  // 地图已判定这是当前有效的情境线索。真实按键、锁定原因、
  // 前置条件及附近交互提示保持原来的本地判定与文字。
  enabled: mapAllowsAiWording, // 仅为未来确认启用后的示例；本轮不接入此hook
  inspectHint, // 仍传地图原来的本地文字，不能再把AI结果回灌这里
  nearTarget: near ? nearTarget : null,
  floor: currentFloor,
  hintKey: currentTargetAndDistanceBand, // 可选，本地缓存键，不发送给模型
  blocked: externalOverlayOpen || gameCommandPending,
  resetKey: journeyOrQAVisitKey,
});

// 在现有 GameScreen 参数上接 hint.text，保持 nearHint 优先的原显示结构。
// 以下仅为保留的技术示意，本轮不要求地图/UI执行这项接线。
<GameScreen {...existingGameScreenProps} inspectHint={hint.text} />
```

`mapAllowsAiWording`、`currentFloor` 和可选的目标/距离档键是接入方的现有运行时值，不是本分支新增的游戏状态字段。没有独立键时，当前提示文字本身也参与去重；不需要为此创建追踪系统。集市、暗道和仓库等多层地图必须提供当前有效的 `floor`，缺少时只使用本地文字。

若后续另行确认启用，工具行为如下；本轮地图不运行这些自动请求：

- 启用与入口须先按最终分工统一确认；hook 自身不创建按钮、面板、箭头、NPC、地图标记或暂停行为。
- 原文立即可用；同一提示稳定800毫秒后才尝试生成。两次尝试至少间隔15秒，不按每帧位置或 revision 发请求，按当前目标/距离档复用内存缓存。
- 每份当前地图进度最多保留64条缓存；换地图、楼层、关键进度、账号或 QA/重开标识时清除。目标完成后由地图清掉原 `inspectHint` 或关闭 `enabled`，工具同步取消旧结果。
- 附近真实交互目标出现、页面隐藏、进入事件/战斗等其他阶段、外部弹层阻断时取消等待。真实 `nearHint` 继续优先显示；不能用 AI 文字替换 E/C/Q/F/S/Space、锁定原因或前置条件。
- 生成失败、超时、限流、上下文冲突或输出不合格时继续原本地文字；同一有效提示不自动重试，不弹错误提示，不阻塞行走。缓存只在内存，不写存档或浏览器持久存储。
- 发往模型的观察只有当前已批准的一句文字。内部目标 ID、距离档键、坐标、开发附表、完整地图和未打开的事件不发给模型；不靠 ID 中的 `trap`、`boss` 等词提前揭示真相。
- 模型返回只显示单句正文（最多80字）；服务端会拒绝明显新增的方向、按键、数字、部分人物/机制词或改变不确定语气的输出。这是附加校验，不能代替地图的资格与可见性判定。

### 4.2 保留的独立短提示请求协议（本轮未启用）

以下保留已有 API 的技术说明。未来确认启用后，不使用 hook 的接入方也可以调用同一个认证接口；本轮地图不发起此类请求：

```ts
const answer = await requestModelAdvisor({
  scope: 'explore_hint',
  sceneKey: journeySceneKey(state),
  expectedRevision: state.revision,
  context: JSON.stringify({hint: approvedLocalHint}),
}, abort.signal);
const text = answer.source === 'model' ? answer.text : approvedLocalHint;
```

本模式不接收 `question`、`history`、`attemptId`、`stageId`；`context` 只允许 `{hint: string}`，文字最多240字，JSON字符串最多2048字。模型最多等待4秒，无重试。客户端调用现有同源接口，继续使用原会话认证，密钥只在服务端。开始核对当前场景和版本，返回前核对相关进度，已经完成的目标或已打开的事件不能收到旧提示。

自动提示的服务端会话槽与主动聊天分开，仍受现有全局并发、日请求预算和每槽六次/分钟限制；它不属于独立计费上限。直接调用接口的接入方需要自行实现与 hook 一样的低频、缓存、取消和原文字回退约定。

## 5. 可选 React 会话工具

`web/src/modules/advisor/AdvisorProvider.tsx` 不包含任何入口按钮、面板或样式，也不会自行暂停游戏。本轮页面负责人只在家园或战斗提供入口；其他阶段关闭聊天并取消未完成请求。家园无需填写地图观察或登记战斗快照。

```tsx
<AdvisorProvider
  state={state}
  catalog={catalog}
  open={advisorOpen && (state.phase === 'home' || state.phase === 'battle')}
  onOpenChange={setAdvisorOpen}
  blocked={externalOverlayOpen || gameCommandPending}
  resetKey={journeyOrQAVisitKey}
>
  {/* 由页面负责人接入自己的页面与聊天界面 */}
</AdvisorProvider>
```

内部可调用：

```ts
const [open, setOpen] = useAdvisorOpen();
const {messages, pendingQuestion, notice, loading, ready, sceneLabel, ask}
  = useGlobalAdvisor();
// 发送按钮：ask(question)。每次发送重新构建当前上下文。
// title/text 和问题按普通文本渲染，不作为HTML或游戏指令执行。
```

- `open/onOpenChange` 由接入方决定，不指定常驻位置或出现时机；本轮仅家园与战斗可以打开入口。
- `blocked` 表示外部操作暂不允许提问。若接入方选择聊天时暂停游戏，不能把聊天自身导致的暂停又传为 `blocked`，否则会取消自己的请求。
- 切换场景/当前观察时，已完成的最近三轮对话可保留，进行中的旧请求会取消。保留的聊天仅作对话上下文：战斗仍只答战斗，家园不把旧战斗数值当实时状态。
- 换会话、重新开始、QA访问变化时清空历史。接入方应为重开/QA提供新的 `resetKey` 并传入新状态。
- 页面隐藏或聊天关闭时取消等待，不自动重发。
