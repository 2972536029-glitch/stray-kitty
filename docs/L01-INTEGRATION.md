# 第一章战斗与正式补给接入

更新：2026-10-25。实现位于现有 `feat/l00-main-integration`，继续使用现有 MR !14 → main，不自动合并。序章局内固定版本保留，新章由 `modules/battle/chapter` 实现。

## 可玩范围

- 新运行关卡 `alley_boss`：12×5 的凸形有效地格、三格垃圾障碍、A5／D12／E12 三路小怪、2×2 四格固定首领、8 波、31 名普通黑影、六位战斗援军。
- 首领普通攻击与动作预告的大招；零漏怪加奖，不要求战斗猫全程不掉血。
- 家园新增最小出战准备入口；服务已救援标志解锁，玩家按真实库存选带。家园完整仓库展示与美术仍由对应 UI 工作接入，本次不另建第二份浏览器仓库。
- 第一至第五章每关一个首领且逐章增强的规则已明确；本轮只落地 L01，尚未实现 L02–L05、正式多章编队或长期招募。

## 装配与生命周期

`App → BattleHost` 按服务端 `activeBattle.stageId` 分派 L00 和 L01。两者都使用原 attemptId、主项目暂停、结果请求和幂等重试。没有第二个宿主计时器。L01 的 `chapter-context` 校验进行中场次、12×5／8 波布局、保存的事件压力与预留清单。

战斗页面以原独立工程迁入的 L00 页面为基准，直接复用其局部样式、休整／军师区域、猫旁技能菜单、速度控件和背包展开方式；只为六猫、12×5 地图和首领补必要的交互适配，不另设计底部技能操作栏。点场上猫查看普攻范围和猫旁技能圆钮，悬停或聚焦图标查看说明，满能后点图标释放或进入选点。地图画面是功能原型，最终地图美术与团队 UI 对齐由对应成员负责。

当前地图有 30 个存在的地格；A6／B6／C6 为垃圾障碍，A5 是出生口，路线为 A5→B5→C5→D5→D1。右侧两路从 D12／E12 出发。Boss 固定占 D10、D11、E10、E11 四格，全部禁止部署／移动／交换进入，小怪可经过；可候选部署格共 19 格。任何一格足迹被合法普攻或技能覆盖都可命中 Boss，同次攻击跨多个足迹格仅结算一次。三入口和四格足迹属于局内规则，服务通过关卡 ID、地图尺寸、波次与结果字段对接，不另传一份碰撞数据。

六只本关援军不会直接写入长期 `cats`。进入和结算沿用团队服务命令；L01 失败仍回准备阶段，准备页以 `lastResult.stageId` 保留本关入口。L01 胜利返回家园，序章剧情首通奖励只由原 `alley_rescue` 路径处理。

标题页、全局暂停、地图／商店／旅程记录、待处理请求和页面隐藏均停止战斗。整页刷新恢复同一活动场次的档位与预留清单；局内棋盘、体力、波次回到 ready，不宣称逐帧恢复。该整场重开同时回退未结算的局内使用，既有预留不会再次扣库存。

## 正式补给事务

公共命令与 OpenAPI 同步新增可选物资字段：

- `START_BATTLE {stageId, supplies?}`：检查真实库存与关卡上限，把物资从可用库存预留到 `activeBattle.supplies`。L00 仍有免费 2 罐＋1 冻干，额外最多 2／1；L01 全量来自仓库，最多 4／2，总计 6。
- `COMPLETE_BATTLE {attemptId, outcome, usedSupplies?, report?}`：L01 要求当前有效自带耗用以及 `{leaks,bossDefeated}`；L00 兼容旧客户端。服务拒绝超额耗用和不合法的报告，归还未用预留并结算奖励。
- `lastResult.battleRewards`：服务确认后的补给清单、基础份数、首胜额外份数、零漏怪额外份数和开局档位。界面据此显示到账，不能自行增加库存。

L00、L01 每次新胜利按 2／3／4 份基础补给发奖，各关跨档首胜 +2。L01 零漏怪再 +1；L00 旧结果没有零漏报告，不擅加该奖励。失败无奖。道具、返还、奖励、首胜与请求收据一起保存，重复请求不重复发放。

现有 Go 单进程 JSON 存档承担这些事务；未引入或部署 MySQL。局内胜负与有效耗用仍由客户端原型报告，服务做字段、上限、场次和重复请求校验，不据此宣称权威战斗模拟或防作弊。L01 的“撤离本场”经二次确认后用既有 COMPLETE_BATTLE 提交 lost，结算实际耗用并返还未用物资，没有单独新增 HTTP 放弃命令；返回标题仍只是暂停，刷新按上述整场重开语义处理。
