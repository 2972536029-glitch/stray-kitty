# 第一章四猫战斗接入

更新：2026-10-26。本次基于main e95c618（已合入探索地图!21）修改两章战斗。第一章由6猫改为4猫，棋盘由12列30格收缩为10列26格，取消战斗道具和休整。

## 玩家流程

开场剧情 → l00_tutorial正式新版L00六波教程 → 小巷探索／纸箱事件 → alley_rescue四猫L01首领战 → 既有救援剧情／家园。家园alley_boss为相同L01的重玩入口。保留团队探索场景与原事件档位判定，缩短的是战斗棋盘。

L00成功不提前发放点点救援首奖；alley_rescue成功保留原伙伴／猫窝／邮票／材料剧情结算。alley_boss重玩不重复救援奖励。长期招募与猫的故事身份不由战斗阵容自动改写。

## 地图和阵容

10列×5行包围框内26有效格，首领在场时15个候选部署格。A–C只存在第4/5列，A5/B5/C5垃圾不可部署；三入口A4/D10/E10，D1保护点；Boss占D8/D9/E8/E9，共享HP，同次攻击只命中一次。首领退场后四格立即开放，候选部署格增至19个；敌人占格等移动限制照常检查。

每模拟秒自动+5能量，100满能后手动释放，无技能冷却或物品补能。体力归零退场，本场不能重新部署；本轮进一步移除伙伴列表侧栏，保留棋盘上方军师入口与场上血条。当前美术分支采用雨后小巷像素旧砖、残留水迹与街角杂物，保留猫旁技能；外围氛围底色不产生新地格，详见[场景美术](../design/tower-defense/scene-art.md)。

保留8波31小怪、Boss普通HP2600、10伤害普攻和70伤害重砸。先判断全部小怪已处理、Boss真正击败和少于3漏才通关；全员退场或第3漏失败。没有战斗补给奖励或零漏物品加奖。

## 契约与兼容

两个L01入口均使用ChapterBattleViewport，真实stageId和attemptId由宿主处理。START_BATTLE不再带supplies；COMPLETE_BATTLE只报告attemptId、outcome及report(leaks,bossDefeated)。新版本不扣／预留／抽取战斗物品，原旧活动场次预留在有效结算／撤离时全额退回一次；既有仓库数据保留。

旧alley_rescue活动场次在刷新后按新版L01从ready重建，沿用场次与难度；旧客户端缺少Boss报告的胜利不能直接认可，需刷新。标题保持原实例暂停，整页刷新不承诺逐帧恢复。L01失败结算继续回准备，新挑战新attempt；没有“失败直接回探索”的改动。

## 验收范围与协作

三档引擎策略使用真实合法技能／移动、每秒观察一次，简单118秒0漏、普通128秒0漏、困难132秒1漏通关，四猫存活；这是引擎结果。2026-10-26 完整检查通过125项前端／战斗测试、Go全包检查、类型／内容／API／架构检查及生产构建。16项浏览器端到端测试全部通过（9.2分钟），包含真实操作完成六波教程→探索事件→四猫Boss→救援剧情／家园，以及L01三档实际通关、猫旁技能、躲避、宽窄屏、失败重试、原库存不变和原故事首奖。最终画面另核对序章标题与原3×7棋盘、第一章26格四猫和点点治疗提示。

规则、接口、单位、技能及旧存档说明见[设计索引](../design/tower-defense/README.md)。战斗场景美术由战斗侧承接，页面 UI 与轩扬协作；探索地图、主流程与家园系统保持团队分工，军师仍用本地规则。后续各章的实现与交付状态见[当前索引](../design/tower-defense/README.md)，独立试玩与正式主线接入分别记录；本文原有第一章玩法和验收结论不随索引更新而改写。
