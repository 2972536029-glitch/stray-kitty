## 0. 一句话定位

随机事件是"探索"和"塔防"之间的**转换器**:探索中撞见事件 → 掷骰与选择 → 产出线索/物资/塔防修正 → 引导进入塔防关卡。Sprint 1 雏形已验证最小循环(点点事件 → 判定 → 塔防 → 寻猫启事)可以跑通;本文件定义**目标形态**,并给出从雏形到目标的迁移路径(§8)。

```
探索地图 → 触发猫咪事件与掷骰判定 → 收集线索和物资 → 塔防关卡 → 解锁伙伴/新区域 → 扩建花房 → 循环
   【v0.5 起逐步落地】     【本模块】                 【闫琦雯】     【王浩哲】      【商店/邮票】
```

## 1. 设计红线(继承自剧情大纲 v0.2,不可违反;雏形已遵守的标 ✅)

1. **非暴力**:任何动物不被消灭。失败不能是死亡,只能损失/绕路/局势变化。✅ 雏形塔防失败=重新布防
2. **失败不卡死主线**:主线猫确定性救回。事件失败只能让路"更狼狈",不能"救不了"。✅ 雏形失败线点点照样入队
3. **剧情整体走向焊死**:章节顺序、伙伴、团圆结局不受骰子影响。失败让玩家走得狼狈,不让故事偏航。✅ 雏形成败两线汇回同一节点
4. **抽卡不卖强度**:猫爪邮票只换家具;主线猫、必要物资不进任何随机池。✅ README 商店规则
5. **猫是行动主体**:事件文案中人类只以痕迹间接出现(寻猫启事、水碗、旧毯子)。✅ 寻猫启事场景

> 雏形的失败线文案("你没有丢下我")本身就是 fail forward 的直觉——本设计把这个直觉制度化并走得更远。

## 2. 触发方式:节点管"你去找事",随机管"事来找你"

| | 节点式 | 随机式 |
|:---|:---|:---|
| 玩法身份 | 机遇/好奇:纸箱、麻袋、寻猫启事、集市摊位 | 风险/氛围:黑影逼近、受惊的狗、突变天气 |
| 谁主动 | 玩家走过去,自己选 | 世界打断玩家 |
| 心理感受 | 掌控感、探索欲 | 紧张感、"这条巷子不对劲" |

- 温暖的东西由玩家**主动**发现(呼应红线 5);危险的东西由世界**主动**找上门(黑影 = 走着走着背后发凉)。
- 随机触发前给**半秒预告拍**(影子一闪、音乐一沉):温暖向不做跳吓,让玩家"有预感地被袭击"。
- **给地图(Jenny)的参数需求**:每区域一个 `危险度(0~3)`,同时管随机事件的**触发频率**与随机池的**类型配比**——一个参数一个含义,地图侧只需维护这一个数字 + 节点摆放数据。
- **抽取规则**:区域随机池 = 该区域全部"机遇+风险"事件;触发时按配比抽 1 张,**无放回**(防"又是麻袋?"的重复感)。池子抽干后剩余路段安全——危险区走深了反而安心,本身是节奏设计。
- **剧情事件永不进随机池**:寻猫启事必须出现在"离开小巷前"的剧情节拍上,由剧情流程摆放。

*现状注记:雏形中事件挂在剧情链(story.json 的 choice 节点),相当于节点式的最早形态,保留;随机式触发与区域池是本模块的核心增量(迁移步骤③)。*

## 3. 事件结构:两根轴 + 四档结果文案

一张事件卡 = **分类 + 标签 + 情境文字 + 2~3 个选项 + 每选项四档结果文案**。

- **分类**(池子轴,决定怎么进池子):机遇 / 风险 / 剧情。
- **标签**(机械轴,决定哪只伙伴的本事管用):陷阱 / 黑影 / 觅食 / 寻路 / 社交。

示例卡(素材来自大纲第四章):

> **【会动的麻袋】** 分类:风险 · 标签:陷阱/黑影 · 触发:节点(诱饵)
> 巷子深处传来挣扎声,一只麻袋在扭动,旁边有新鲜的爪痕。是受困的伙伴,还是诱饵?
> - **A. 直接扑上去解绳结** — 大成功:救出小猫,+1 线索,+1 邮票;成功:救出小猫 +1 线索;有代价:救出,但黑影记住了你们(下场塔防黑影压力 +1 档)⚑;失败:是空诱饵,黑影从背后逼近,触发紧急撤离⚑
> - **B. 沿墙根绕到下风口先看** — 大成功:看清真相,顺手偷到旁边罐头;成功:看清真相再决定;有代价:看清了,但天黑前时间耗尽(本区域强制触发下一事件);失败:气味被风搅乱,白跑一趟
> - **C.(墨墨在场才显示)让墨墨贴暗处摸过去** — v1.2 落地为正常掷 2d6(围绕"看清"的四档结果);原案的"免掷"形态列为 v2 备选

⚑ = Outcome 的塔防修正与局势通道(§6)。

**目标 schema(events.json v2,雏形字段的迁移对照见 §8)**:

```json
{
  "moving_sack": {
    "title": "会动的麻袋",
    "prompt": "巷子深处传来挣扎声……",
    "category": "风险",
    "tags": ["陷阱", "黑影"],
    "options": [
      {
        "id": "rush", "label": "直接扑上去解绳结", "icon": "🐾",
        "outcomes": {
          "crit":    { "text": "救出小猫!",  "reward": { "clue": 1, "stamps": 1 } },
          "success": { "text": "救出小猫。", "reward": { "clue": 1 } },
          "partial": { "text": "救出,但被黑影盯上…", "reward": { "clue": 1 }, "tdMod": { "shadowPressure": 1 } },
          "fail":    { "text": "是空诱饵!黑影从背后逼近!", "situation": "forced_chase" }
        }
      }
    ]
  }
}
```

## 4. 判定规则:喵喵掷 2d6,四档结算(轻判定)

**谁掷**:永远是喵喵掷(玩家 = 喵喵);伙伴不改骰子、只改局面。

**为什么 2d6**:两颗骰子是钟形曲线,中间结果最常见——而"中间结果"是叙事最有肉的部分。

| 骰点 | 结果 | 语义 | 概率 |
|:---|:---|:---|:---|
| 12 | 大成功 | 额外彩蛋(多一张邮票 / 多一条线索) | 2.78% |
| 9~11 | 成功 | 干净拿到目标 | 25% |
| 6~8 | 成功但有代价 | 拿到目标,但局面变复杂 | 44.44% |
| 2~5 | 失败 | 拿不到目标,**局势推进**(fail forward) | 27.78% |

*(精确分布 1/36、9/36、16/36、10/36;早期版本误把 12 重复计入成功档写成"9+ 约 28%",已修正。档位数字试玩后可调;结构是 PbtA《Apocalypse World》一脉三档判定的无属性简化版,加大成功档。)*

**"有代价"当主档的原因**:红线 1 规定失败不能是死亡,所以失败必须有意思——"成功但有代价"与"失败但局势推进"让每次掷骰都推进故事,而不是惩罚玩家。雏形用二元成败,失败后的剧情分支只能整段另写;四档制让第三档承担"赢了但…"的叙事空间,失败档专职"局面变化",文案效率更高。

**伙伴技能 = 标签匹配,三种不同形状**(不挂数值,v1.1 随伙伴入队逐步启用):

| 伙伴 | 生效标签 | 效果 | 味道 |
|:---|:---|:---|:---|
| 点点 | 陷阱 | **识破**:该事件各选项的后果提前可见("???"翻译成人话) | 观察型:不替你选,让你看清赌注 |
| 墨墨 | 黑影 | **夜视**:该事件多一个隐藏的安全选项 | 侦查型:给你多一条路 |
| 团子 | 觅食/寻路 | **讨生活**:该类事件失败时仍保底拿到一半物资 | 老江湖型:摔了也不空手回 |

三人一个给信息、一个给选项、一个给保底——探索编队因此有真实取舍,而实现成本是零数值系统。雏形已有 `trust`(点点信任)字段,是伙伴关系的天然挂点。

## 5. 事件分类与产出

| 分类 | 怎么触发 | 产出 |
|:---|:---|:---|
| **机遇** | 节点为主,随机池少量配 | 鱼干 / 邮票 / 线索 |
| **风险** | 随机为主;诱饵类做节点 | **高方差**:成功给超额奖励 |
| **剧情** | 只做节点,**永不进随机池** | 剧情 flag、情绪 |

硬规则:**风险事件的成功必须给超额奖励**——风险 = 高方差机遇,不是纯惩罚。黑影盘踞的角落里藏着一整箱鱼干,随机遇袭才是"要不要赌"的心跳时刻,而不是"运气差被扣血"。

## 6. 成败输出契约(Outcome)

事件结算输出一个结构化"后果包",各模块按需订阅,互不需要理解对方内部:

```
事件结算 → Outcome {
  资源:     fish / stamps / clue / material      // 经济系统(商店/花房建设)
  难度档位:  shadowPressure(±1)→ low/medium/high   // 传给塔防,三档数值由闫琦雯设计
  局势:     forcedEvent?: id, 绕路, 紧急撤离        // 事件系统内部消化(已实现:跳转指定剧情节点)
  剧情flag:  diandian_trust / light_found / ...    // 王浩哲订阅;先记录,后利用
}
```

**难度档位接口(与战斗模块的正式约定,2026-10-22 与闫琦雯对齐)**:事件卡的 `tdMod.shadowPressure`(±1,main 已实现并做范围校验)在进入战斗前映射为三档难度传给塔防:**-1 → low(简单)、0 → medium(普通)、+1 → high(困难)**;同一段流程里多场事件时,**最后一场带修正的结果生效**(与 main 当前 `PendingModifiers` 行为一致)。档位由事件结果产出——不由玩家选、不由战斗侧改,三档的战斗数值由闫琦雯负责设计。玩家在事件里的表现直接决定下一场战斗的松紧,这是"风险 = 高方差"闭环的最后一环。

- **局势通道不可砍**:若成败只碰资源和难度,两场战斗之间的一次失败就"没有任何事发生",骰子死了。
- **剧情 flag 不是分支承诺**:先记账,给将来的差异化剧情留数据接口;读不读、何时读由剧情组决定。

## 8. 与 Sprint 1 雏形的差异与迁移

### 8.1 差异清单(设计为准,雏形待升级)

| 维度 | 雏形(v1.0.0) | 目标形态(本文件) |
|:---|:---|:---|
